# 任务看板 — 版本更新说明

面向：**发版的人**（如何发布新版本）与 **使用者**（如何升级）。

当前分发方式为 Windows **portable 单文件**（`任务看板-x.y.z.exe`），不自动覆盖安装，需下载新文件替换旧程序。

---

## 一、使用者怎么升级

1. 打开应用 → **设置** → **关于**
2. 查看当前版本号，点击 **检查更新**
3. 若提示有新版本：
   - 阅读更新说明
   - 点击 **打开下载页**，下载新的 exe
4. **完全退出**旧程序后，用新 exe 替换（可覆盖同名文件，或换新文件名后删掉旧文件）
5. 重新打开即可；任务数据一般在本机数据目录，**不会**因换 exe 而丢失

若检查失败（网络、更新源未配置等）：向发版人索取下载链接，按上面第 4 步手动替换。

---

## 二、发版人怎么通知大家升级

### 2.1 一次性准备工作（只需做一次）

1. 准备一个**可公网或内网访问**的静态地址，用于放更新信息 JSON，例如：
   - 对象存储（OSS / COS）
   - 公司内网静态站
   - GitHub Releases + raw / 直链
2. 修改源码里的更新源地址并重新打包：

   文件：`src/main/appUpdate.js`

   ```js
   const UPDATE_FEED_URL = 'https://你的域名/kanban-latest.json';
   ```

3. 之后每次发版，只需改 JSON + 上传 exe（见下文），**不必**再改程序里的 URL（除非换域名）。

示例 JSON 模板见：`docs/kanban-latest.example.json`。

### 2.2 每次发版步骤

1. **改版本号**  
   编辑 `package.json` 的 `"version"`，例如 `"1.0.0"` → `"1.0.1"`（建议遵循 `主版本.次版本.修订号`）。

2. **打包**  
   在项目根目录执行：

   ```bash
   npm run build
   ```

   产物一般在 `dist/`，文件名类似：`任务看板-1.0.1.exe`。

3. **上传安装包**  
   把 exe 上传到下载站，记下**可直接下载**的 HTTPS（或 HTTP）地址。

4. **更新 feed JSON**  
   在 `UPDATE_FEED_URL` 指向的地址发布（覆盖）如下内容：

   ```json
   {
     "version": "1.0.1",
     "notes": "修复编辑时剪贴板填图；支持检查更新",
     "url": "https://你的域名/releases/任务看板-1.0.1.exe"
   }
   ```

   | 字段 | 必填 | 说明 |
   |------|------|------|
   | `version` | 是 | 最新版本号，须 **大于** 用户正在用的版本，应用才会提示更新 |
   | `url` | 是 | 新 exe 的下载页或直链，须以 `http://` 或 `https://` 开头 |
   | `notes` | 否 | 简短更新说明，会显示在「关于」里 |

5. **通知用户**（可选但建议）  
   群公告 / 邮件：说明新版本号、主要改动，并提示到 **设置 → 关于 → 检查更新**。

### 2.3 版本比较规则

- 按 `主.次.修订` 数字比较（可带前缀 `v`，如 `v1.0.1`）。
- 仅当远程 `version` **高于** 本地版本时提示「发现新版本」。
- 相等或远程更低：显示「已是最新版本」。

---

## 三、自测清单

发版后建议自己验证一遍：

- [ ] 旧版（版本号更低）打开 → 设置 → 关于 → 检查更新 → 出现新版本与「打开下载页」
- [ ] 点「打开下载页」能打开正确链接
- [ ] 用新版再检查 → 显示已是最新
- [ ] 故意写错 JSON / 关掉网络 → 有明确错误提示，程序不崩

---

## 四、注意

- **占位地址**：若仍使用 `https://example.com/kanban-latest.json`，检查更新会失败，属预期；请换成真实地址后重新打包再分发。
- **数据安全**：升级只换程序文件；数据在应用数据目录。重大变更若涉及数据格式，应在 `notes` 里写清楚，并尽量保持向后兼容。
- **不自动覆盖**：当前不做静默安装/自动替换，避免 portable 场景下误伤用户文件。
