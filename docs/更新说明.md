# 任务看板 — 版本更新说明

面向：**发版的人**（如何发布新版本）与 **使用者**（如何升级）。

当前分发方式为 Windows **portable 单文件**（`task-kanban-x.y.z.exe`）。应用内可一键下载并自动替换**用户双击的那个 exe**后重启（portable 运行时会解压到临时目录，升级必须覆盖 `PORTABLE_EXECUTABLE_FILE`，不能只换临时目录里的文件）。

---

## 一、使用者怎么升级

1. 打开应用 → **设置** → **关于**
2. 查看当前版本号，点击 **检查更新**
3. 若提示有新版本：点击 **立即更新**
4. 等待下载完成；程序会自动退出、替换 exe，并重新打开新版本
5. 任务数据在本机数据目录，**不会**因换 exe 而丢失

若自动替换失败（例如程序目录无写权限）：文件会落到「下载」文件夹，按提示退出后手动覆盖即可。

若检查失败（网络、更新源未配置等）：向发版人索取下载链接，手动下载后替换旧 exe。

---

## 二、发版人怎么通知大家升级

### 2.1 更新源（已配置）

应用内「检查更新」会请求：

`https://raw.githubusercontent.com/ITimesGo/task-kanban/main/docs/kanban-latest.json`

对应仓库文件：`docs/kanban-latest.json`。  
改版本信息后 **提交并推送到 `main`**，用户即可查到；一般**不必**再改 `src/main/appUpdate.js` 里的 URL。

下载地址建议使用 GitHub Release 资源直链，例如：

`https://github.com/ITimesGo/task-kanban/releases/download/v1.0.1/task-kanban-1.0.1.exe`

### 2.2 每次发版步骤

1. **改版本号**  
   编辑 `package.json` 的 `"version"`，例如 `"1.0.0"` → `"1.0.1"`（建议遵循 `主版本.次版本.修订号`）。

2. **更新 feed JSON**  
   编辑 `docs/kanban-latest.json`（只保留最新一版）。

3. **本地打包**  

   ```bash
   npm run build
   ```

   产物：`dist/task-kanban-x.y.z.exe`（请用英文名上传 Release，避免中文被剥掉导致 404）。

4. **提交推送 + 发 GitHub Release**  

   ```bash
   git add package.json docs/kanban-latest.json
   git commit -m "chore: release 1.0.1"
   git push
   ```

   然后打开 https://github.com/ITimesGo/task-kanban/releases/new ，Tag 用 `v1.0.1`，上传 exe 并 Publish。  
   详见 `docs/发版简易.md`。

5. **通知用户**（可选）  
   群公告 / 邮件：说明新版本号，并提示到 **设置 → 关于 → 检查更新**。

### 2.3 版本比较规则

- 按 `主.次.修订` 数字比较（可带前缀 `v`，如 `v1.0.1`）。
- 仅当远程 `version` **高于** 本地版本时提示「发现新版本」。
- 相等或远程更低：显示「已是最新版本」。

## 三、自测清单

发版后建议自己验证一遍：

- [ ] 旧版（版本号更低）打开 → 设置 → 关于 → 检查更新 → 出现新版本与「立即更新」
- [ ] 点「立即更新」显示下载进度，随后自动退出并重启为新版本
- [ ] 用新版再检查 → 显示已是最新
- [ ] 故意写错 JSON / 关掉网络 → 有明确错误提示，程序不崩

---

## 四、注意

- **数据安全**：升级只换程序文件；数据在应用数据目录。重大变更若涉及数据格式，应在 `notes` 里写清楚，并尽量保持向后兼容。
- **自动替换**：打包版下载完成后会退出进程，由脚本覆盖当前 exe 并重启；开发模式或目录无写权限时退回「仅下载」。
- **raw 访问**：若部分网络打不开 `raw.githubusercontent.com`，检查更新会失败，但仍可通过 Release 页面手动下载。
