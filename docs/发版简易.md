# 发版（简易）

仓库：https://github.com/ITimesGo/task-kanban  

在本机打包 exe，再上传到 GitHub Release（比云端自动打包更快）。

---

## 发一版要做的事

### 1. 改版本号
打开 `package.json`，改 `"version"`，例如：

```json
"version": "1.0.1"
```

### 2. 更新「检查更新」信息
编辑 `docs/kanban-latest.json`（只保留最新一版，直接覆盖）：

```json
{
  "version": "1.0.1",
  "notes": "这里写给用户看的更新说明",
  "url": "https://github.com/ITimesGo/task-kanban/releases/download/v1.0.1/任务看板-1.0.1.exe"
}
```

### 3. 本地打包

```powershell
npm run build
```

生成：`dist/任务看板-1.0.1.exe`（文件名里的版本号随 package.json）。

### 4. 提交并推送代码

```powershell
git add package.json docs/kanban-latest.json
git commit -m "chore: release 1.0.1"
git push
```

### 5. 上传到 GitHub Release
1. 打开 https://github.com/ITimesGo/task-kanban/releases/new  
2. Tag 填：`v1.0.1`（`v` + 版本号；选 Create new tag）  
3. 标题例如：`任务看板 v1.0.1`  
4. 把 `dist/任务看板-1.0.1.exe` 拖进附件  
5. 点 **Publish release**

### 6. 告诉别人
把 Release 链接发出去。用户打开软件后，若检测到新版本，**设置按钮**和「关于」会出现小红点。

---

## 核对清单

- [ ] `package.json` 的 version 已改  
- [ ] `kanban-latest.json` 的 version / notes / url 已改  
- [ ] `npm run build` 成功，`dist/` 里有对应 exe  
- [ ] 代码已 `git push`  
- [ ] Release 已发布，附件是对的 exe  
- [ ] 旧版点「检查更新」能看到新版本  

---

## 注意

- `url` 里两处版本号都要改：`.../download/v1.0.1/` 和 `任务看板-1.0.1.exe`。  
- 用户下载后关掉旧程序，用新 exe 替换即可；任务数据一般不会丢。  
- 不再使用 GitHub Actions 自动打包。
