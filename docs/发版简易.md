# 发版（简易）

仓库：https://github.com/ITimesGo/task-kanban  

推送版本 tag（如 `v1.0.1`）后，**GitHub Actions 会自动打包并创建 Release**，一般不用再手动上传 exe。

---

## 发一版要做的事

### 1. 改版本号
打开 `package.json`，改 `"version"`，例如：

```json
"version": "1.0.1"
```

（后面的 tag 必须是 `v` + 这个数字，如 `v1.0.1`。）

### 2. 更新「检查更新」信息
编辑 `docs/kanban-latest.json`：

```json
{
  "version": "1.0.1",
  "notes": "这里写给用户看的更新说明",
  "url": "https://github.com/ITimesGo/task-kanban/releases/download/v1.0.1/任务看板-1.0.1.exe"
}
```

### 3. 提交并推送代码

```powershell
git add package.json docs/kanban-latest.json
git commit -m "chore: release 1.0.1"
git push
```

### 4. 打 tag 并推送（触发自动发版）

```powershell
git tag v1.0.1
git push origin v1.0.1
```

然后打开 Actions 看进度：  
https://github.com/ITimesGo/task-kanban/actions  

成功后 Release 在：  
https://github.com/ITimesGo/task-kanban/releases  

### 5. 告诉别人
把 Release 链接发出去。用户打开软件后，若检测到新版本，**设置按钮**和「关于」会出现小红点。

---

## 核对清单

- [ ] `package.json` 的 version 已改  
- [ ] `kanban-latest.json` 的 version / notes / url 已改  
- [ ] 代码已 `git push`  
- [ ] 已推送 tag：`v` + 版本号（与 package.json 一致）  
- [ ] Actions 跑成功，Release 里有 exe  
- [ ] 旧版点「检查更新」能看到新版本  

---

## 注意

- **不要**只改 version 不打 tag——不推 `v*` tag，就不会自动发版。  
- tag 与 `package.json` 不一致时，Actions 会失败（有意为之，防止发错版）。  
- 本地可选 `npm run build` 自测，不是发版必需。  
- 用户下载后关掉旧程序，用新 exe 替换即可；任务数据一般不会丢。  
- 若自动发版失败，仍可按旧方式手动：本地打包后到 Releases 页面上传 exe。
