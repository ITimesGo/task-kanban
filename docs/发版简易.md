# 发版（简易）

仓库：https://github.com/ITimesGo/task-kanban  

改 `package.json` 的 `"version"` 并推送到 `main` 后，**Actions 会自动打 tag、打包、创建 Release**（一般不用再手动 `git tag`）。

---

## 发一版要做的事

### 1. 改版本号
打开 `package.json`，改 `"version"`，例如：

```json
"version": "1.0.1"
```

### 2. 更新「检查更新」信息
编辑 `docs/kanban-latest.json`（只保留最新一版，直接覆盖）：

```json
{
  "version": "1.0.1",
  "notes": "这里写给用户看的更新说明",
  "url": "https://github.com/ITimesGo/task-kanban/releases/download/v1.0.1/任务看板-1.0.1.exe"
}
```

### 3. 提交并推送（自动打 tag + 发版）

```powershell
git add package.json docs/kanban-latest.json
git commit -m "chore: release 1.0.1"
git push
```

然后打开 Actions 看进度：  
https://github.com/ITimesGo/task-kanban/actions  

成功后 Release 在：  
https://github.com/ITimesGo/task-kanban/releases  

### 4. 告诉别人
把 Release 链接发出去。用户打开软件后，若检测到新版本，**设置按钮**和「关于」会出现小红点。

---

## 核对清单

- [ ] `package.json` 的 version **比上一版更高**  
- [ ] `kanban-latest.json` 的 version / notes / url 已改  
- [ ] 已 `git push` 到 `main`（且本次提交改动了 `package.json`）  
- [ ] Actions 跑成功，出现 tag `v版本号`，Release 里有 exe  
- [ ] 旧版点「检查更新」能看到新版本  

---

## 注意

- 只有 **version 数字变了** 才会自动发版；只改其它文件不会触发。  
- 同一版本号不要发两次（已有 `v1.0.1` tag 会跳过）。  
- 仍可手动：`git tag v1.0.1 && git push origin v1.0.1`（兼容旧流程）。  
- 本地可选 `npm run build` 自测，不是发版必需。  
- 用户下载后关掉旧程序，用新 exe 替换即可；任务数据一般不会丢。
