# 简易任务看板（桌面版）设计文档

日期：2026-08-03
技术栈：Electron + 原生 HTML/CSS/JS

## 1. 技术架构

**Electron + 原生 HTML/CSS/JS（无前端框架）**

- 应用规模小，用 Vue/React 会引入不必要的构建复杂度。原生 JS 配合 Electron 三层结构足够清晰。
- **进程分工**：
  - **Main 进程**：文件系统（读/写 JSON、图片复制/删除）、剪贴板图片读取、托盘、窗口生命周期、强制落盘。
  - **Preload 脚本**：通过 `contextBridge` 暴露安全白名单 API（`window.taskAPI`）给渲染进程，隔离 Node 权限。
  - **Renderer 进程**：纯 UI —— 渲染任务列表、处理点击/粘贴/筛选，通过 `taskAPI` 与 main 通信。
- **存储**：JSON 文件，路径 `%APPDATA%/TaskApp/tasks.json`；图片存 `%APPDATA%/TaskApp/images/`（符合需求 §4.2）。
- **打包**：electron-builder 生产便携版（绿色文件夹版，免安装、免管理员）。静态文件直接拷贝。

## 2. 数据模型与持久化

**任务对象**（严格对应需求 §4.1）：

```js
{
  id: "GUID字符串",
  text: "文字内容，可为空",
  images: ["images/{taskId}_1.png", ...],  // 相对路径，最多5张
  status: "pending" | "done",
  createdAt: "ISO 8601",
  updatedAt: "ISO 8601"
}
```

**图片路径解析**：`images` 中存的是相对路径，其解析基准为 `%APPDATA%/TaskApp/`。即展示/删除时用 `path.join(APP_DATA_DIR, relativePath)` 得到绝对路径；`%APPDATA%/TaskApp/` 由 main 进程统一提供，renderer 只持有相对路径。

**图片存储**：
- 上传/粘贴时，renderer 先把图片字节交给 main，main 复制到 `%APPDATA%/TaskApp/images/{taskId}_{序号}.{ext}`，再把该相对路径存入任务。
- **5 张上限在创建和编辑两条路径都要强制**：创建面板与详情编辑态均拦截第 6 张。
- 编辑时删除图片 → 同时物理删除对应图片文件；重命名会导致多任务共享同一张图，所以每张图严格归属于单一任务（**复制而非引用**），删除任务时该任务的所有图片一并清理（需求 F-09、验收最后一条）。

**持久化可靠性**：
- 任何变更（创建/编辑/删除/标记完成）后立即把整个任务数组写入 JSON（`fs.writeFileSync` 原子写：先写临时文件再重命名），满足"崩溃不丢数据"。
- **持久化统一走 main 进程**，renderer 不直接碰文件系统。所有写操作由 main 串行执行，避免并发写坏文件。

## 3. 界面布局与交互

**主窗口**（默认 800×600，可缩放，中文界面）：

```
┌──────────────────────────────────────────────┐
│ 简易任务看板    [全部][待执行][已执行]          │
├──────────────────────┬───────────────────────┤
│                      │  创建任务面板(40%)      │
│  任务卡片列表(60%)    │  多行文字输入框         │
│  卡片                 │  [添加图片] [粘贴区]    │
│  卡片                 │  缩略图行(预览/删除)    │
│  卡片                 │  [创建任务]            │
│                      │                       │
└──────────────────────┴───────────────────────┘
```

**任务卡片**：
- 白色圆角卡片，左侧状态色条（待执行=蓝、已执行=灰）。
- 文字摘要前 3 行省略，右侧/右下显示第一张图片缩略图。
- 右下角创建时间，右上角快捷完成/取消按钮（F-10/F-11）。
- 已执行：文字加删除线、整体灰化弱化。

**创建面板**：
- 多行文本框（支持 ≥500 字）。
- [添加图片] 按钮 → 文件选择器（jpg/png/bmp，≤10MB，单选或多选）。
- 面板内可 Ctrl+V 粘贴（剪贴板读图，F-02）。
- 已添加图片以缩略图展示在输入框下方，可点开放大预览、可单独移除。
- [创建任务]：文字和图片都为空 → 提示"请至少输入文字或添加图片"（验收最后一条）。

**详情弹窗**（模态）：
- 点击卡片打开，展示完整文字、所有图片（点击放大）、创建时间、状态。
- 底部 [编辑]、[删除] 按钮。
- [编辑] → 变为可编辑状态，支持改文字、增删图片、[保存]。
- [删除] → 二次确认 → 移除任务并清理图片文件。
- [标记完成/取消完成] 在详情里也要可操作（F-10/F-11 卡片上也有）。

**托盘（Tray）**：最小化到托盘，点托盘图标恢复窗口。需要一份托盘图标资源（随应用打包，建议内置小尺寸 .ico/.png）。关闭按钮行为：点击窗口 X 默认隐藏到托盘（不退出），通过托盘菜单"退出"彻底退出并结束进程。

## 4. 错误处理与测试

**错误处理**：
- 图片文件缺失/损坏时，列表与详情应优雅降级（显示占位图标，不崩溃）。
- 无效的图片粘贴内容（非图片格式）→ 忽略并提示。
- JSON 文件损坏 → 备份原文件、以空列表启动，不丢用户预期。
- 图片读取权限失败 → 显示错误提示而非静默失败。

**测试策略**：
- **编辑/删除/标记/过滤/创建约束** 这些数据操作逻辑放在一个纯 JS 模块（`taskStore.js`）里，与 UI 解耦，可做单元测试。
- 用 Node 内建 test runner（node:test）对 taskStore 的增删改、状态切换、图片路径管理、JSON 持久化做单元测试。
- 图片复制/删除、剪贴板粘贴等文件/剪贴板操作通过 main 进程封装，做集成测试。
- 手动验收：按需求 §7 的验收标准逐条过一遍（启动、创建带图任务、Ctrl+V 粘贴、重启持久化、标记已执行样式、删除清理图片、空内容提示）。

## 5. 功能需求覆盖对照

| 需求 | 实现位置 |
|------|---------|
| F-01 多行文字 | 创建面板文本框 |
| F-02 添加图片（按钮/粘贴/上限5张） | 创建面板 + main 剪贴板 |
| F-03 缩略图预览与删除 | 创建面板缩略图行 |
| F-04 创建任务（空内容拦截） | taskStore + 创建面板 |
| F-05 卡片列表展示 | renderer 列表渲染 |
| F-06 按创建时间倒序 | taskStore 排序 |
| F-07 查看详情 | 详情弹窗 |
| F-08 编辑任务 | 详情弹窗编辑态 |
| F-09 删除任务（二次确认+清理图片） | 详情弹窗 + main 文件清理 |
| F-10 标记已执行（删除线/弱化） | renderer + taskStore |
| F-11 取消已执行 | renderer + taskStore |
| F-12 过滤视图 | renderer 筛选标签 |

## 6. 非功能性需求覆盖

- 性能：JSON 全量内存操作，<500 条读写轻松满足启动 <2s、操作 <200ms。
- 可靠性：原子写 + 立即落盘。
- 界面：800×600 可缩放、托盘最小化、简体中文。
- 兼容性：Electron 支持 Win10 1809+，独立 exe，免安装运行环境。
- 分发：electron-builder 便携版绿色文件夹，无需管理员权限。
